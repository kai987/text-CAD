# 日本の二階建て一戸建て：パラメトリック計画モデル

[简体中文](README.md) | **日本語** | [English](README.en.md)

現在の図面版はR02（日本の製図基準を準用した版）です。**ユーザーが承認したR01の間取りは変更していません**。三次元モデルも同じ間取りを使用しています。室名、面積、寸法、建具番号、家具の文字は、背景に対して読み取りやすい色で表示します。

## オンラインで表示

[住宅CADビューアを開く](https://kai987.github.io/text-CAD/)。キャンバス上部で、建物全体／1階内部／2階内部を切り替えられます。部品ツリーでは、各階、外壁、間仕切り、床、扉、窓、収納、階段、屋根の表示・非表示を操作できます。名前または三次元の部品をクリックするとハイライトされ、元の部品名を確認できます。「単独」で選んだ分類だけを表示し、上部のプリセットで表示を戻せます。回転、拡大・縮小、水平断面表示にも対応しています。平面図ページは室と寸法を標準表示し、R02のA3図枠全体へ切り替えられます。ベクター表示の拡大と、編集可能なDXFのダウンロードに対応しています。ファイルページではSTEP、GLB、DXF、PDF、パラメータの説明を提供しています。

言語選択で**简体中文、日本語、English**を切り替えられます。選択を保存していない場合は中国語が初期表示となり、選んだ言語は同じブラウザで次回も復元されます。切り替えはすぐに画面の文章へ反映され、現在のページ、階、視点、断面、部品の表示・選択、平面図の拡大率は維持されます。ウェブの室別一覧は選んだ言語の室名を表示します。元のCAD、PDF、SVG図面の日本語注記と、元の部品名は変更しません。上部のリンクで、このリポジトリのREADMEの言語版も切り替えられます。

ヘッダーの「表示モード」で自動／ライト／ダークを選べます。初回はOSの外観設定に従い、選択は同じブラウザに保存されます。「自動」ではOSの外観変更にも追従します。切り替えても視点、部品の表示・選択、断面高さ、平面図の拡大率を維持します。ダークモードでは画面と三次元背景を変更しますが、元のCAD、PDF、SVG図面の紙面は読みやすい白地を維持し、印刷用ファイルも変更しません。

ウェブアプリは`web/`にあり、React、TypeScript、Three.js、Viteを使用しています。ローカルのPythonビューアは不要です。生成済みGLBを直接読み込むため、CADの形状は変更しません。STEPとDXFは元ファイルをダウンロードできます。オンライン平面図は元のPDFから変換したSVGを使用し、すべての文字を字形の輪郭へ変換しているため、閲覧者の日本語・中国語フォントに依存しません。用紙全体の内容はそのまま維持し、平面図表示には同じSVGの切り抜きビューポートを使っています。縦横の全体寸法、室名、建具番号、開閉円弧、北矢印を保持しています。モデル内には元の`F1`、`F2`、`stairs`、`roof`と各階内の六分類のノードが残り、GLTFLoaderのノードインデックスとの対応から元の名前を復元します。スマートフォンではタッチで回転・拡大できます。WebGLを実行できないブラウザでは、選択中のプリセットに対応する静止画を表示します。

Node.js 24、またはそれ以降の互換バージョンを使用してください。

```bash
cd web
npm ci
npm test
npm run dev
# 本番用ビルドとローカルプレビュー
npm run build
npm run preview
```

Rust/WASM の断面試作は `rust/section-caps/` にあります。標準では TypeScript を使い、[Rust 試作を有効にする](https://kai987.github.io/text-CAD/?view=3d&mode=second&section=wasm)と必要時に WASM を読み込みます。ダウンロードや初期化が失敗した場合は TypeScript に戻ります。ページ切り替えでも試作パラメータを維持し、元の CAD は変更しません。Rust は `f64` で計算し `f32` を出力します。孔、収納の断面、階段の開口、法線、座標変換を既存実装と比較しています。まだ Worker は使わず、画面のメインスレッドで計算します。

Apple M1 Pro、Node 24.18.0 でウォームアップ後に150回測定しました。1バッチは111個の不透明メッシュと4高さ（1200／2700／4200／5600 mm）を処理し、データ変換、輪郭線、解放を含みます。中央値は TypeScript 3.360 ms、Rust/WASM 2.379 ms でした。79,235バイトの WASM の初回コンパイルと初期化は15.199 msでした。ネットワーク、ブラウザのフレーム、GPU描画は含まれず、画面のフレームレート向上を示す値ではありません。以下は `web/` で実行します。通常のテストと公開では保存済み WASM を使用し、Rust のインストールは不要です。

```bash
npm run bench:sections -- --edges
# Rust コアを変更した後に再生成。Rust 1.93.0 を使用
cargo install wasm-bindgen-cli --version 0.2.114 --locked
npm run build:wasm
npm test
npm run build
```

`build:wasm` は Rust のネイティブテストを実行し、WASM／JS バインディングとソース・生成物のハッシュを作成します。通常のテストとビルドは古い生成物を拒否します。独立した Rust ワークフローはネイティブテスト、Clippy、WASM コンパイルを実行します。ベンチマークは `--output /absolute/path/result.json` で結果を保存できます。

開発とビルドでは、二つの階のベクタープレビューを含む15個のCAD・図面・説明ファイルをリポジトリからコピーし、SHA-256一覧を生成します。本番用ビルドではコピーを再確認します。ベクターメタデータには元PDFのハッシュ、SVGのハッシュ、切り抜き内の注記範囲も記録しています。元PDFが変わった場合やSVGが一致しない場合はビルドを停止し、再変換を求めます。`web/public/artifacts/`、派生データ、`web/dist/`はGitへコミットしません。

計画を変更した場合は、まずCADとPDFを再生成し、対応する検証を完了してからベクタープレビューを更新してください。変換ツールはローカルでPythonを使用します。GitHub Pagesのビルドはコミット済みSVGを直接読み込みます。

```bash
uv pip install --python .venv/bin/python PyMuPDF==1.26.7
.venv/bin/python web/scripts/generate-plan-svg.py
```

`output/vector/house_1f_plan.svg`、`house_2f_plan.svg`、`web/src/plan-preview-metadata.json`をコミットして再ビルドします。現在の切り抜き範囲と必須ラベルは、承認済みの7,280 mmのデモ計画に対応しています。平面の寸法や用紙のレイアウトを変える場合は、切り抜き範囲と注記を再確認してください。

`.github/workflows/pages.yml`は`main`へのプッシュ時に、依存関係のインストール、モデル操作のテスト、TypeScriptのチェック、ビルド、ファイルハッシュの確認を実行し、GitHub Pagesへ公開します。オンラインで表示する寸法もデモ用の仮定です。構造・設備配管等の未確定事項は以下に記載しています。

## ファイル

- `src/lib/house_plan.py`：二つの階に共通するmm単位のパラメータ、室内の有効境界、壁、建具開口、家具の占位、仮定。
- `src/generate_plans.py`：ezdxfによる編集可能なTEXT／DIMENSION注記と住宅平面図の生成。同時に、A3横・1:50・全2ページの確認用PDFを出力。
- `src/lib/jp_drafting.py`、`src/lib/jp_sheet.py`：基準に準用したレイヤ名、紙面の字高・線幅、および共通のA3図枠、表題欄、面積表、注記。
- `DXF/001D0PL2-1FPLAN.DXF`、`DXF/002D0PL2-2FPLAN.DXF`：R02の命名規則を準用した各階の平面図。
- `DXF/house_1f_plan.dxf`、`DXF/house_2f_plan.dxf`：R2018形式、mm単位、モデル空間1:1。
- `output/pdf/house_floor_plans_R02_JP.pdf`：現在の二つの階の平面図、図枠、表題欄、面積表、仮定。A3の実際のサイズで印刷し、自動拡大・縮小は使わないでください。R01のPDFは旧版として残しています。
- `docs/tokyo_cad_standard_mapping_R02.md`：参照基準の章・ページ、住宅への準用方法、対応していない項目。
- `checks/validate_jp_drafting.py`、`output/review/validation_jp_drafting.json`：保存後のレイヤ、字高、色、線幅、ネイティブ寸法、ペーパー空間の検証。
- `output/review/design_manifest.json`：機械可読のパラメータ、すべての仮定、室別面積。
- `checks/validate_plans.py`：現在の間取りの形状、扉、階段、保存済みDXFの検証。
- `output/review/validation.json`：実際の検証結果と未検証事項。
- `src/lib/house_geometry.py`：承認済み平面を使う三次元パラメータ、壁の開口、床、切妻屋根、建具、U字階段。
- `src/house_3d.py`：三次元アセンブリの入口。STEPとGLBを再生成。
- `STEP/house_3d.step`：mm単位の精密ソリッド。`F1`、`F2`、`stairs`、`roof`と部品ごとに命名。同じ場所の`.step.json`にCADgenビューアのマテリアル等のメタデータを保存。
- `GLB/house_3d.glb`：m単位、Y軸上向きの標準glTF 2.0。部品名と階層を保持し、Blender等で表示・編集可能。
- `output/review/house_3d_assumptions_R01.json`：三次元モデルのデモ用パラメータと具体的な仮定。
- `checks/validate_3d.py`、`output/review/validation_3d.json`：保存済みSTEPソリッドとGLBの単位、名前、階層等の検証。

## 計画

座標はXが東、Yが北です。南側玄関と北向きはデモ用の仮定であり、敷地や道路の資料はまだありません。

1階：南側のLDK（20.17 m²）、南東の玄関と靴収納、北側の浴室、洗面・脱衣室、食品庫、東側のトイレ、北東の階段。浴室へは洗面・脱衣室から入ります。

2階：主寝室（10.45 m²）、洋室2（L字形、正確な面積8.895 m²）、洋室3（9.17 m²）、納戸、トイレ、共用廊下。トイレへは廊下の北側から入り、寝室を通りません。元図面の室名は「主寝室」「洋室 2」「洋室 3」「納戸」です。

上下階のトイレと階段は同じ位置にあります。北東のU字階段は、16段の蹴上げ、蹴上げ175 mm、踏面260 mm、各階段幅900 mm、中間踊場900 mmです。階段室に1,900 × 2,720 mmを確保し、2階床には階段室全体の開口を設けています。

DXFの可視レイヤはすべてACI 7とし、図形はByLayerで色を継承します。固定RGBは指定しません。CADビューアでは暗い背景で白、明るい背景で黒となり、室名、建具番号、家具文字を読み取れます。PDFは白地に黒い線と文字を使用します。背景を変えてもモデルの再生成は不要です。

## R02の製図基準準用

[東京都建設局 CAD製図基準（令和6年4月）](https://www.kensetsu.metro.tokyo.lg.jp/documents/d/kensetsu/000067788)の共通項目に基づき図面を調整しています。同文書は土木を対象とし、この住宅案では共通の製図規則を準用しています。適用判断と根拠となる章は対応記録に示しています。住宅の施工図や電子納品の全要件への適合を意味しません。

用紙はA3横、縮尺は1:50を維持しています。基準はA1を標準としますが、必要に応じてA列サイズを選択できます。四辺の余白は7.5 mm、輪郭線は0.70 mmです。右下に60 × 45 mmの表題欄を置き、日付を和暦で記載しています。一般図形の線幅は0.13／0.25／0.50 mm、寸法線は0.13 mmです。紙面上の字高は室名3.5 mm、寸法・面積2.5 mm、小注記1.8 mm、タイトル5 mmとし、モデル空間の字高は紙面字高の50倍です。

`D-STR-WALL`、`D-STR-DIM`等のレイヤ名に、責任主体／図面オブジェクト／作図要素の構成を採用しています。住宅用に追加した要素の意味も記録しています。ネイティブDIMENSIONと文字は引き続き編集できます。

図枠と表題欄は、DXFの**`JP_A3_1_50`ペーパー空間レイアウト**に保存し、1:50のビューポートをロックしています。PDFは用紙全体を表示します。text-to-cadのブラウザビューアはモデル空間を表示するため、ペーパー空間の図枠は表示しません。旧ファイル名のDXFと命名規則を準用したDXFは同じ内容で、既存のビューアリンクも使えます。

SXF(P21/P2Z)、DRAWING.XML、電子納品用フォルダは出力していません。既存の三次元STEPとGLBは変更していません。STEPと二次元電子納品のSXF(P21)は異なる形式です。

## 明示した仮定と未確定事項

1. 外形7,280 × 7,280 mm、階高2,800 mmは、ユーザー指定の**デモ用仮定**です。
2. 外壁180 mm、内壁100 mmは占位パラメータであり、木構造や建築構法を設計した値ではありません。
3. 室の注記は壁内法寸法を使用し、面積には家具の占有部分を含みます。階段面積は確保した階段室の面積で、2階では床開口を含みます。各階53.00 m²、合計106.00 m²は外形の幾何学的面積のみを示し、そのまま法定の建築面積・床面積としては使えません。
4. 扉の幅は図面上の開口幅で、枠厚をまだ控除していません。寝室の扉は室内側へ開きます。引戸は壁内の戸袋に収納する占位表示で、実際の戸袋、金物、有効開口幅は詳細検討が必要です。
5. 承認済みのトイレは900 × 1,700 mmでコンパクトです。食品庫は片側に幅350 mmの棚を仮配置し、残りの通路は730 mmです。主な通行経路としては扱いません。
6. 浴室と洗面・脱衣室は各4.95 m²とし、承認済みの面積配分を維持しています。
7. 家具、厨房設備、浴槽、衛生器具、窓は寸法上の占位であり、製品を選定したものではありません。階高と室内の有効高さは異なります。
8. 三次元モデルの追加仮定：床厚200 mm、扉開口高さ2,100 mm。大きい窓の窓台高さ900 mm・窓高さ1,300 mm、小さい窓の窓台高さ1,500 mm・窓高さ600 mm。切妻屋根の勾配30°、軒の出450 mm、屋根の鉛直厚150 mm。いずれも施工仕様として確定していません。
9. 構造、敷地条件、設備配管、法定面積、建築法令への適合は未検証です。実際の階段頭上の有効高さは、床、梁、仕上げが決まった後で確認する必要があります。

三次元モデルの仕上げ面基準はZ=0、2,800 mmで、床板は基準面の下に置いています。壁の有効高さは仮に2,600 mmです。屋根下にも200 mm厚の概念上の上部スラブを設け、上端をZ=5,600 mmとしています。中間踊場は200 mm厚です。各半階段には260 mmの踏面が7つあり、踊場と2階床がそれぞれ8つ目の蹴上げを形成します。階段は概念上の段状ソリッドで表現し、手すり、階段梁、構造接合は詳細検討の対象です。

壁には扉上部と窓の上下の壁を残し、開口位置は承認済み平面を使用しています。三次元の扉は閉じた位置、平面図の扉は開く方向を表示します。靴収納と収納棚は、部品名を持つ寸法上の占位ソリッドです。

## 再生成と表示

```bash
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python src/generate_plans.py
.venv/bin/python checks/validate_plans.py
.venv/bin/python checks/validate_jp_drafting.py
.venv/bin/python src/house_3d.py
.venv/bin/python checks/validate_3d.py
.venv/bin/python -m playwright install chromium
CADGEN_DAEMON=0 .venv/bin/cadgen dxf snapshot DXF/house_1f_plan.dxf output/review/house_1f_cad.png --appearance light
CADGEN_DAEMON=0 .venv/bin/cadgen dxf snapshot DXF/house_2f_plan.dxf output/review/house_2f_cad.png --appearance light
.venv/bin/cadgen viewer --host 127.0.0.1 --json --detach
```

最後のコマンドは実際のビューアURLを返します。`URL?file=DXF%2Fhouse_1f_plan.dxf`、`URL?file=DXF%2Fhouse_2f_plan.dxf`、`URL?file=STEP%2Fhouse_3d.step`、`URL?file=GLB%2Fhouse_3d.glb`をそれぞれ開いてください。ビューアは閲覧専用です。平面または三次元のパラメータを変更したら、対応する生成ツールと検証を再実行します。STEPの部品ツリーで、各階、壁、床、建具、階段、屋根を個別に表示・非表示にできます。

バックグラウンドのスナップショット処理で繰り返し文字が欠ける事象があったため、上記の一時ワーカープロセスを使用し、文字が揃った画像を生成しています。PDFとDXFの元のTEXTは別途確認しています。

PDFにはmacOSの`Arial Unicode.ttf`を使用しています。ほかのOSへ移す場合は、生成ツールのフォントパスを更新してください。DXFの文字と寸法は編集できますが、CADソフト側にも日本語・中国語を表示できるフォントが必要です。

## text-to-cadのワークフロー

公式の[CAD](https://github.com/earthtojake/text-to-cad/blob/main/skills/cad/SKILL.md)と[DXF](https://github.com/earthtojake/text-to-cad/blob/main/skills/dxf/SKILL.md)の手順を使用し、ランタイムを`cadgen[snapshot]==0.7.11`に固定しています。参照した上流ソースのバージョンは`8d795f56343edce7ef6b9413e02f7a92318f8229`で、ローカルの参照資料は`.tools/text-to-cad/`にあります。

公式の`@dxf`出力契約は製造用形状を対象とし、文字を輪郭へ変換するため、この案ではユーザーの許可に基づき、ezdxfで建築平面の編集可能な文字、寸法、建具レイヤを直接作成しています。その後、cadgenのチェックとビューアで確認します。

## 今後の詳細検討

現在のファイルはパラメトリックな計画モデルです。実際の敷地、構造形式、壁・屋根の層構成、建具製品、戸袋、階段手すり、設備配管は詳細検討が必要です。必要な専門的確認が完了するまでは、施工図として使用できません。

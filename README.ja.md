## 家具と住宅設備の詳細化（R02-3D / A02-3D）

## 読み込みと操作の改善

オンラインモデルは可逆 GZIP 転送を使用します。一戸建ては 8.03 MB から 3.08 MB、集合住宅は 5.21 MB から 2.30 MB に縮小しました（十進 MB）。展開後のバイト列は元の GLB と一致します。圧縮ファイルが取得できない場合や展開非対応のブラウザーでは元の GLB に切り替え、ダウンロードには元のファイルを提供します。構造レイヤーも圧縮、タイムアウト、キャンセルに対応します。転送量の削減であり、描画速度の向上を示すものではありません。

断面操作をサイドバー上部に配置し、部材一覧に中日英の名称・元の ID による検索と全展開・全折りたたみを追加しました。検索は一覧のみを絞り込み、階のチェックは階全体に作用します。モバイルでは一覧を初期状態で折りたたみ、構造説明とパラメーターを必要に応じて開けます。表示と選択の状態は保持します。

## オンラインで表示

[住宅CADビューアを開く](https://kai987.github.io/text-CAD/)。キャンバス上部で、建物全体／1階内部／2階内部を切り替えられます。部品ツリーでは、各階、外壁、間仕切り、床、扉、窓、収納、階段、屋根の表示・非表示を操作できます。名前または三次元の部品をクリックするとハイライトされ、選択した言語の部品名を確認できます。「単独」で選んだ分類だけを表示し、上部のプリセットで表示を戻せます。回転、拡大・縮小、水平断面表示にも対応しています。平面図ページは室と寸法を標準表示し、R13のA3図枠全体へ切り替えられます。ベクター表示の拡大と、編集可能なDXFのダウンロードに対応しています。ファイルページではSTEP、GLB、DXF、PDF、パラメータの説明を提供しています。

ページを開くと、選択中の間取りの3Dモデルと全階の平面図を並行して読み込みます。平面図やダウンロードのページから入った場合も3Dシーンを準備します。タブ切り替えでは解析済みの図面を再利用し、3Dの視点、断面、選択状態を維持します。間取りを変更すると旧3Dシーンを解放し、新しい間取りを先読みします。初回のダウンロード中は読み込み状況を表示します。

言語選択で**简体中文、日本語、English**を切り替えられます。選択を保存していない場合は中国語が初期表示となり、選んだ言語は同じブラウザで次回も復元されます。切り替えはすぐに画面の文章へ反映され、現在のページ、階、視点、断面、部品の表示・選択、平面図の拡大率は維持されます。ウェブの室別一覧は選んだ言語の室名を表示します。元のCAD、PDF、SVG図面の日本語注記と、元の部品名は変更しません。上部のリンクで、このリポジトリのREADMEの言語版も切り替えられます。

ヘッダーの「表示モード」で自動／ライト／ダークを選べます。初回はOSの外観設定に従い、選択は同じブラウザに保存されます。「自動」ではOSの外観変更にも追従します。切り替えても視点、部品の表示・選択、断面高さ、平面図の拡大率を維持します。ダークモードでは画面と三次元背景を変更しますが、元のCAD、PDF、SVG図面の紙面は読みやすい白地を維持し、印刷用ファイルも変更しません。

ウェブアプリは`web/`にあり、React、TypeScript、Three.js、Viteを使用しています。ローカルのPythonビューアは不要です。生成済みGLBを直接読み込むため、CADの形状は変更しません。STEPとDXFは元ファイルをダウンロードできます。オンライン平面図は元のPDFから変換したSVGを使用し、すべての文字を字形の輪郭へ変換しているため、閲覧者の日本語・中国語フォントに依存しません。用紙全体の内容はそのまま維持し、平面図表示には同じSVGの切り抜きビューポートを使っています。縦横の全体寸法、室名、建具番号、開閉円弧、北矢印を保持しています。モデル内には元の`F1`、`F2`、`stairs`、`roof`と各階内の八分類のノードが残り、GLTFLoaderのノードインデックスとの対応から元の名前を復元します。スマートフォンではタッチで回転・拡大できます。WebGLを実行できないブラウザでは、選択中のプリセットに対応する静止画を表示します。

```bash

npm run dev
# 本番用ビルドとローカルプレビュー
```

Rust/WASM の幾何コアは `rust/section-caps/` にあります。断面の閉鎖面と壁・外壁パネル・妻壁の CAD 輪郭線は、標準で専用 Worker 内で計算します。Three.js の頂点バッファは画面側に保持し、Worker には独立コピーを一度登録します。断面高さを連続変更した場合、実行中の1バッチと最新の待機高さだけを保持し、古い結果を適用しません。住宅モデルを切り替えると旧 Worker を終了します。WASM・Worker の初期化、通信、計算の失敗やタイムアウト時は TypeScript に戻ります。`section=wasm` は引き続き利用でき、`section=typescript` で従来アルゴリズムと比較できます。この指定はモデル・図面ページの切り替えでも保持します。CAD、平面図、視点、部材名は計算エンジンの変更で変わりません。

Rust は `f64` で計算し `f32` を出力します。孔、収納の閉鎖面、階段開口、法線、座標変換、壁の同一平面の継ぎ目を従来アルゴリズムと比較します。ベンチマークは現在の住宅 GLB と1階仕上げ面の高さ基準を使い、TypeScript／WASM の断面と CAD 輪郭線を別々に測定します。Node の測定には Worker の転送・待機、ネットワーク、画像デコード、GPU 描画を含まず、画面のフレームレートを示すものではありません。以下は `web/` で実行します。通常のテストと公開は保存済み WASM を使うため、Rust のインストールは不要です。

現在のモデルを Node 23.7.0／macOS arm64 で30回ウォームアップし、150回測定しました。1断面バッチは745個の不透明メッシュと4高さを処理し、閉鎖面のエッジを含む中央値は TypeScript 32.259 ms、Rust/WASM 30.781 ms でした。24個の壁の輪郭線では2.500 msと0.886 msでした。直接アルゴリズムの測定であり、画面側の負荷は Worker のスケジューリングと描画にも依存します。

`build:wasm` は Rust のネイティブテストを実行し、WASM／JS バインディングとソース・生成物のハッシュを作成します。通常のテストとビルドは古い生成物を拒否します。独立した Rust ワークフローはネイティブテスト、Clippy、WASM コンパイルを実行します。ベンチマークは `--output /absolute/path/result.json` で結果を保存できます。

### Python のネイティブ Rust 空間チェック

`rust/spatial-core/` を PyO3 で Python に接続し、Rust の BVH で家具、扉の開閉範囲、収納前、キッチン、通路、室領域の包囲ボックス候補をまとめて絞ります。実際の重複面積と室内への包含は Shapely／GEOS で判定し、既存の境界、孔、微小面積のしきい値に関する意味を維持します。構造部材も Rust で候補を絞り、正確な BRep 交差判定は CAD カーネルで行います。Rust はポリゴンの面積・包含を直接計算しません。パラメトリック形状、STEP 出力、DXF 注記は既存の Python 処理を維持します。寸法、クリアランス、設計条件は引き続きデモ用仮定であり、計算エンジンの変更は構造・法規の適合認証を意味しません。

梁・柱・基礎・小屋裏部材の支持チェックにも Rust の接触候補抽出を適用しました。面がちょうど接する場合と 0.001 mm の許容範囲内の候補を含め、最終的な距離と共通面積は CAD カーネルで計算します。各検証では変更しない形状の境界と面をキャッシュし、部材の順序を維持します。今回、木造ソースモデルの910項目と保存済み W／S／RC モデルの2,987項目を従来の全レポートと比較し、すべて一致しました。

GLB 検証ではバイナリの頂点・法線・三角形インデックスを直接読みます。Rust で有限値、インデックス範囲、バッファ範囲と実際の境界を検証し、宣言された POSITION 境界と照合します。本プロジェクトの稠密 float32 三角形出力、インターリーブされたバッファ、3種類の符号なしインデックス幅に対応し、スパース・圧縮・その他のプリミティブは明示的なエラーにします。面積ゼロの三角形は診断として記録します。多様体性、法線の方向や構造安全性は判定しません。既存の5つの GLB は計1,568メッシュ、373,811頂点、587,954三角形で、Rust と独立した Python デコーダーの全レポートが一致しました。

## 追加した2LDKマンション住戸（A01）

DXFの可視レイヤはすべてACI 7とし、図形はByLayerで色を継承します。固定RGBは指定しません。CADビューアでは暗い背景で白、明るい背景で黒となり、室名、建具番号、家具文字を読み取れます。PDFは白地に黒い線と文字を使用します。背景を変えてもモデルの再生成は不要です。

## R02の製図基準準用

[東京都建設局 CAD製図基準（令和6年4月）](https://www.kensetsu.metro.tokyo.lg.jp/documents/d/kensetsu/000067788)の共通項目に基づき図面を調整しています。同文書は土木を対象とし、この住宅案では共通の製図規則を準用しています。適用判断と根拠となる章は対応記録に示しています。住宅の施工図や電子納品の全要件への適合を意味しません。

用紙はA3横、縮尺は1:50を維持しています。基準はA1を標準としますが、必要に応じてA列サイズを選択できます。四辺の余白は7.5 mm、輪郭線は0.70 mmです。右下に60 × 45 mmの表題欄を置き、日付を和暦で記載しています。一般図形の線幅は0.13／0.25／0.50 mm、寸法線は0.13 mmです。紙面上の字高は室名3.5 mm、寸法・面積2.5 mm、小注記1.8 mm、タイトル5 mmとし、モデル空間の字高は紙面字高の50倍です。

`D-STR-WALL`、`D-STR-DIM`等のレイヤ名に、責任主体／図面オブジェクト／作図要素の構成を採用しています。住宅用に追加した要素の意味も記録しています。ネイティブDIMENSIONと文字は引き続き編集できます。

図枠と表題欄は、DXFの**`JP_A3_1_50`ペーパー空間レイアウト**に保存し、1:50のビューポートをロックしています。PDFは用紙全体を表示します。text-to-cadのブラウザビューアはモデル空間を表示するため、ペーパー空間の図枠は表示しません。旧ファイル名のDXFと命名規則を準用したDXFは同じ内容で、既存のビューアリンクも使えます。

SXF(P21/P2Z)、DRAWING.XML、電子納品用フォルダは出力していません。既存の三次元STEPとGLBは変更していません。STEPと二次元電子納品のSXF(P21)は異なる形式です。

## 明示した仮定と未確定事項

1. 外形7,280 × 7,280 mm、階高2,800 mmは、ユーザー指定の**デモ用仮定**です。
2. 外壁180 mm、内壁100 mmは占位パラメータであり、木構造や建築構法を設計した値ではありません。
3. 室の注記は壁内法寸法を使用し、面積には家具の占有部分を含みます。階段面積は確保した階段室の面積で、2階では床開口を含みます。各階53.00 m²、合計106.00 m²は外形の幾何学的面積のみを示し、そのまま法定の建築面積・床面積としては使えません。
4. 扉の幅は図面上の開口幅で、枠厚をまだ控除していません。寝室の扉は室内側へ開きます。引戸は壁内の戸袋に収納する占位表示で、実際の戸袋、金物、有効開口幅は詳細検討が必要です。
5. ユーザー確認済みのトイレは900 × 1,700 mmでコンパクトです。食品庫は片側に幅350 mmの棚を仮配置し、残りの通路は730 mmです。主な通行経路としては扱いません。
6. 浴室と洗面・脱衣室は各4.95 m²とし、ユーザー確認済みの面積配分を維持しています。
7. 家具、厨房設備、浴槽、衛生器具、窓は寸法上の占位であり、製品を選定したものではありません。階高と室内の有効高さは異なります。
8. 三次元モデルの追加仮定：床厚200 mm、扉開口高さ2,100 mm。大きい窓の窓台高さ900 mm・窓高さ1,300 mm、小さい窓の窓台高さ1,500 mm・窓高さ600 mm。切妻屋根の勾配30°、軒の出450 mm、屋根の鉛直厚150 mm。いずれも施工仕様として確定していません。
9. 構造、敷地条件、設備配管、法定面積、建築法令への適合は未検証です。実際の階段頭上の有効高さは、床、梁、仕上げが決まった後で確認する必要があります。

三次元モデルの仕上げ面基準はZ=0、2,800 mmで、床板は基準面の下に置いています。壁の有効高さは仮に2,600 mmです。R06では小屋裏に厚24 mmの下地床（上面Z=5600 mm）と独立した木造構造案を設けます。中間踊場は200 mm厚です。各半階段には260 mmの踏面が7つあり、踊場と2階床がそれぞれ8つ目の蹴上げを形成します。階段は概念上の段状ソリッドで表現し、手すり、階段梁、構造接合は詳細検討の対象です。

壁には扉上部と窓の上下の壁を残し、開口位置はユーザー確認済み平面を使用しています。三次元の扉は閉じた位置、平面図の扉は開く方向を表示します。靴収納と収納棚は、部品名を持つ寸法上の占位ソリッドです。

最後のコマンドは実際のビューアURLを返します。`URL?file=DXF%2Fhouse_1f_plan.dxf`、`URL?file=DXF%2Fhouse_2f_plan.dxf`、`URL?file=STEP%2Fhouse_3d.step`、`URL?file=GLB%2Fhouse_3d.glb`をそれぞれ開いてください。ビューアは閲覧専用です。平面または三次元のパラメータを変更したら、対応する生成ツールと検証を再実行します。STEPの部品ツリーで、各階、壁、床、建具、階段、屋根を個別に表示・非表示にできます。

バックグラウンドのスナップショット処理で繰り返し文字が欠ける事象があったため、上記の一時ワーカープロセスを使用し、文字が揃った画像を生成しています。PDFとDXFの元のTEXTは別途確認しています。

PDFにはmacOSの`Arial Unicode.ttf`を使用しています。ほかのOSへ移す場合は、生成ツールのフォントパスを更新してください。DXFの文字と寸法は編集できますが、CADソフト側にも日本語・中国語を表示できるフォントが必要です。

## text-to-cadのワークフロー

公式の[CAD](https://github.com/earthtojake/text-to-cad/blob/main/skills/cad/SKILL.md)と[DXF](https://github.com/earthtojake/text-to-cad/blob/main/skills/dxf/SKILL.md)の手順を使用し、ランタイムを`cadgen[snapshot]==0.7.11`に固定しています。参照した上流ソースのバージョンは`8d795f56343edce7ef6b9413e02f7a92318f8229`で、ローカルの参照資料は`.tools/text-to-cad/`にあります。

公式の`@dxf`出力契約は製造用形状を対象とし、文字を輪郭へ変換するため、この案ではユーザーの許可に基づき、ezdxfで建築平面の編集可能な文字、寸法、建具レイヤを直接作成しています。その後、cadgenのチェックとビューアで確認します。

## 今後の詳細検討

現在のファイルはパラメトリックな計画モデルです。実際の敷地、構造形式、壁・屋根の層構成、建具製品、戸袋、階段手すり、設備配管は詳細検討が必要です。必要な専門的確認が完了するまでは、施工図として使用できません。

### CAD公開前検証と読み込み復旧

この最適化段階はR13です。その後R14で左右反転し、収納高さ、階段、掃出し窓、壁厚、バルコニー内法面積などの3言語の数値説明をモデルのパラメータから生成します。

- 全モデル・図面を再生成して検証：`.venv/bin/python src/cad_pipeline.py --regenerate`
- ソースと成果物の対応を確認して保存物を検証：`.venv/bin/python src/cad_pipeline.py --validate`
- 公開前の高速チェック：`python3 src/cad_release.py`

`output/review/cad_release.json`はソース・成果物のハッシュ、ツールチェーン、フォント、完了した生成・検証手順を記録します。CADソース変更後に古い成果物を使うWebビルドを拒否し、Pages公開もCAD検証ジョブを必須とします。検証レポートの実行日時は成果物の照合から除きます。作図フォントは`TEXT_CAD_CJK_FONT=/absolute/path/CJK.ttf`で設定でき、標準は従来のmacOSフォントです。保存物検証には同じフォントのインストールは不要ですが、再作図には利用可能なCJK TTFを指定してください。R05/R06/R10のダウンロードパスは互換性のために保持し、実バージョンは図枠とmanifestで確認します。

主モデルはダウンロード進捗と60秒のダウンロード・解析期限を備え、失敗後に再試行できます。古いリクエストと遅延結果は破棄します。WebGL復旧時には視点、表示部材、切断、昼夜、構造選択を保持して再構築します。初回失敗時の未初期化カメラは復元しません。

検証対象は概念形状・ファイル整合性・閲覧動作であり、構造耐力・法令適合・施工可能性の証明ではありません。
